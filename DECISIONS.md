# Decisions Log

Why the app is built the way it is. One line of reasoning each, newest last.

| # | Decision | Reasoning |
|---|---|---|
| 1 | Zero-install browser app instead of the PRD's React + Python + Docker stack | The owner is non-technical; a stack needing four developer toolchains is not "locally deployable". Full stack is preserved as the Pro Edition roadmap. |
| 2 | All data in browser localStorage; JSON export as the backup | No server means no accounts, no hosting, no data leaving the machine. |
| 3 | Claude API key stored under a **separate** storage key from the diagnostic | So an Export file can never contain it. The data contract actively rejects any state carrying a key. |
| 4 | Direct browser → Anthropic calls (`anthropic-dangerous-direct-browser-access`) | Single-user local app; the key is the owner's and never touches an intermediary server. |
| 5 | `mock` as a magic API key | Lets the owner try every AI feature free and offline, and lets every automated test run without calling the real API. |
| 6 | One shared `schema.js` validated at runtime *and* in tests | This is what keeps "backend" and "frontend" aligned in a single-file app — a shape change on either side fails the contract test. |
| 7 | Trajectory shows `? Unknown` rather than a guessed "stable" | Prediction honesty: a cell with no evidence has no direction. Guessed arrows are the failure mode of predictive dashboards. |
| 8 | Momentum = 50% version history + 50% leading indicators, thresholds ±0.25 | Deliberately simple so any forecast can be explained to a board in one sentence; no black box. |
| 9 | Vendored pdf.js, SheetJS, JSZip into `app/js/vendor/` | Local parsing of PDF/Word/PowerPoint/Excel without asking the owner to install anything. Apache-2.0 / MIT, safe to redistribute. |
| 10 | PDF and image payloads held in memory only, never persisted | Keeps exports small and private; the app honestly asks for re-attach after a restart rather than silently losing content. |
| 11 | Value chain added as a **precursor** layer, not an afterthought | A capability is only critical if money or risk rides on it. Without economic weight, "weakest first" over-prioritises cheap weaknesses. |
| 12 | Board ranks by value exposure (weight × gap) when levers are mapped, weakest-first otherwise | Automatic best-available behaviour; the basis is always stated in the view so the ranking is never mysterious. |
| 13 | Roles scored on **two independent axes**, not one seniority score | Market scarcity (hard to hire) and tacit-knowledge intensity (hard to rebuild) are different risks with different fixes — succession bench vs knowledge capture. A one-axis view misses the quiet experts. |
| 14 | Routing thresholds fixed at 3.5 on both axes and shown in the UI | An auditable rule beats a tuned-in-secret one; reviewers can challenge the threshold rather than the vibe. |
| 15 | Role level suggestions from documents are never auto-applied | The model proposes; the human scores. Preserves the audit trail and the owner's accountability for every rating. |
| 16 | Two separate registers (critical-role and key-person) | One combined list hides knowledge-drain exposure — the exact failure the two-axis rubric exists to prevent. |
| 17 | Nav grouped "Diagnose" / "Ground it" rather than adding an eighth flat tab | Eight equal tabs is a menu; two groups is a workflow — evidence and economics feed the reads. |
| 18 | The value chain **calibrates the cluster set**, not just the ranking | Scoring an industry preset's rows carefully still answers a question about the wrong six things. Four automatic tests — ownership, materiality, separability, diagnosability — check whether these are the right clusters for *this* organisation's money. |
| 19 | Calibration runs in two passes: deterministic first, Claude second | Arithmetic on the owner's own numbers is checkable, offline, and never wrong about itself. The harvest is only for what arithmetic cannot know — how the industry organises the same capability. |
| 20 | No structural change (add / merge / rename / split) is ever auto-applied | Changing the cluster set changes what the whole diagnostic is about. Every proposal needs a click, and merge/remove states plainly what it discards. |
| 21 | The calibration prompt must be allowed to return `keep` | A calibration that changes everything is a rewrite. Forcing the model to justify *no* change is what stops it inventing work. |
| 22 | Industry presets ship starter levers at **0% weight** | The preset knows the *shape* of a money map in that industry; only the owner knows the numbers. Seeding a plausible weight would be a fabricated economic figure, which the rest of the app is built to refuse. |
| 23 | Matrix, Board and Trajectory share one ordering basis | Three views ranking the same clusters three ways is three priority stories. One control, one basis, stated in each view. |
| 24 | Every Signal Matrix row carries its share of the P&L | A maturity score with no materiality beside it invites the board to fix the cheapest gap first. |
| 25 | The methodology's weaknesses ship **inside the app**, not in a doc | A board will find single-rater scoring and the one-snapshot baseline anyway. Naming them first is what makes the strengths credible; a methodology page that only advertises is marketing. |
| 26 | Every watch-out must carry a mitigation | A caveat with no action is an excuse. The test suite fails the build if any limitation lacks one. |
| 27 | Blueprint counters read live state | A static picture ages into a lie. Binding the diagram to the real diagnostic means any claim can be checked against the reader's own data. |
| 28 | Badge/explanation parity enforced both ways in tests | The diagram and the assessment are two representations of one thing; without a test they drift apart on the first edit. |
| 29 | Population guidance lives in the view, collapsed — not in the README | People fill in the Value Chain while looking at the Value Chain. Guidance one tab away is guidance not read; guidance always open is clutter. |
| 30 | Ten role criteria cut to six | Three Axis-A criteria were all measuring consequence, Axis B carried a cross-axis duplicate, and a 10% weight on a 1–5 scale could never cross the 3.5 threshold. Fewer, non-overlapping criteria beat more criteria for rater agreement. |
| 31 | The test for keeping a criterion is "does it point at a different remedy?" | Criteria that lead to the same action are one criterion wearing two names. Six criteria, six remedies. |
| 32 | "Codifiability" renamed "Locked in heads" | The old scale ran 1–5 toward *more* tacit, so a 5 meant "not codifiable" — backwards from its own label. Renaming removes the ambiguity; documenting it would have preserved it. |
| 33 | Every criterion carries written 1/3/5 anchors and an explicit "not" boundary | Anchored scales are the largest lever on inter-rater agreement, and the boundary line is what stops one reason raising two scores. |
| 34 | Definitions open from the column header, not a manual | Guidance read at the moment of scoring is guidance used. The same cards are also reachable as a full six-criterion guide. |
| 35 | Legacy scores migrate deterministically, never reset to 3 | A rubric change must not silently destroy last quarter's judgements or re-route a role. The migration runs on saved state, JSON import, old CSV headers and LLM replies, and the tests assert routing is preserved. |
| 36 | Hand-off format defined here, not copied | None of the three sibling apps mentions the Compass, so there was nothing to match. The packet is shaped around fields they already accept (Org Modeling's criteria and strategy text, Process Map Studio's engagement scope card, the Workbench's role list). |
| 37 | Evidence grade is the assessor's judgement, never derived (owner decision) | Real evidence is fragmentary. The app shows what a grade rests on but does not compute it from a source count. |
| 38 | One rater per cell stays (owner decision) | The playbook's two-rater rule is dropped for this app; the default evidence rules say so explicitly. |
| 39 | IDs are never reused within a workspace | An ID quoted in a board paper must mean the same thing a year later, even after the row it named is deleted. |
| 40 | The active workspace stays under the original storage key | A diagnostic saved before workspaces existed becomes the first workspace with nothing to migrate; other workspaces are parked under their own keys. |
| 41 | New, demo and imported diagnostics each become a new workspace | Nothing the owner starts can overwrite the diagnostic on screen. |
| 42 | The Stage 0 lock can be applied with items open | A gate that blocks is rigid; a gate that can be skipped silently is not a gate. Open items are warned, then written into the decision log at the moment of locking. |
| 43 | Navigation follows the six stages; every workspace opens on the Journey | Twelve destinations in workflow order, with one "next step", replace nine unordered tabs. |
| 44 | A redraw waits while the mouse is down | A field's change fires as it loses focus, usually the mouse-down of the next button. Redrawing then swallowed the click. Found by the charter browser test; fixed app-wide. |
| 45 | The comparison unit is **country** (owner decision, 2026-11-13) | The owner's question is how roles, decision rights and ways of working differ by geography. One workspace per country keeps each country's evidence and scoring separate and honest. |
| 46 | A country is added by copying the **frame**, never the scores | Same clusters, levers, roles, charter and IDs; every judgement blank. Comparison by ID only works if `CAP-03` means the same thing everywhere, and a copied score would be a fabricated one. |
| 47 | A role copied to another country is "to confirm" | It is neither counted as filled nor reported as a gap until someone there says. Assuming it exists would hide exactly the difference the exercise is looking for. |
| 48 | Unscored is never weak | A country or cell nobody has assessed reads "Not scored" and is left out of averages, gaps and money at risk. Level 1 is a finding; blank is not. |
| 49 | Every difference is classed Required / Chosen / Inherited, by the owner | "The countries differ" is not a decision. The class is what turns a difference into an ask: leave local, decide, or harmonise. It is a judgement, so the app never proposes one. |
| 50 | The comparison is stored once per family of countries | Classes, verdict and ask live outside any one workspace, so they read the same whichever country is open, and still travel inside each export. |
| 51 | Importing a findings file never changes a score | The other apps supply evidence; the assessor scores. Only the agreed fields are kept, an unknown grade is dropped, and a file for a different country is flagged. |
| 52 | The EXCO readout is assembled, not written | Six pages counted or quoted from the workspaces. The owner writes two things: the verdict and the ask. No AI narrative, so every line can be traced to a score or a finding. |
| 53 | Money is never added across currencies | A total across countries is offered only when currency and unit match on every one. Otherwise each country shows its own figure. |
| 54 | A value stream keeps its `VS-nn` across countries and re-selection | Process Map Studio can only compare two countries' maps of the same process if both carry the same pilot ID. A copied country, or a pilot dropped and chosen again, reuses the remembered ID, name and KPI; a different cluster never takes it. |
| 55 | Findings may say what they are about (`topic`), why (`reason_class`) and against which country (`compared_with`) | Placing findings on readout pages by guessing from their wording was a stop-gap. The sending app knows; the fields are optional and additive, so format 1.0 stands and older files still import. |
| 56 | `reason_class` uses the Compass's own three words, plus "not known" | Required / Chosen / Inherited is how the owner classes every difference between countries; the other apps must speak the same words, or the readout mixes two vocabularies for one idea. |
| 57 | New kinds `role_reason` (Org Modeling) and `variation` (Process Map Studio, ID `Vn`); `T-nnn` listed for the Workbench | Why a role is in a country, and how two countries' maps differ, are the two inputs the current-state readout lacked. Each is minted by the app that owns the evidence. |
| 58 | A country difference is reported once, by the country being compared | If both countries' files carried it, the readout would show every difference twice. The reference country's file stays clean. |
| 59 | The samples the other apps build against are generated from the Compass demo and imported by its own tests | A hand-written sample drifts from what the Compass actually reads. `scripts/make_country_samples.js` rebuilds them; the contract suite imports them on every run. |
| 60 | Not scored is not Level 1 (owner review, 2026-11-21) | A blank workspace read as 28 failing cells and ranked clusters as if everything were absent. Unscored cells are now left out of every total; choosing a level is the act of scoring, and Clear score undoes it. On load, cells that already carry a level, rationale or evidence are marked scored, so nothing counted before disappears. |
| 61 | A version must hold scores to be a baseline | Empty versions produced a false "Improving" trend the moment real scores arrived. They are now ignored by trends and the scoreboard; saving one warns (Save anyway stays), and versions can be deleted, with a reason if they hold scores. |
| 62 | Cluster scope: Scored, Enabler, Context only | Some clusters are scored but carry no money by design (leadership); some are out of scope this cycle (JV). Context only is entered once and also becomes the Hand-off decision, so nothing is asked twice. |
| 63 | Renaming asks keep-or-new-ID only once the ID has travelled | Before an ID is scored, versioned, handed off or copied, a rename is just a rename. After that, a change of meaning gets a new ID and the old one is retired, so an ID never names two things. |
| 64 | Units: the unit word is on-screen wording only | The data field stays `country`, so the other apps are unaffected. Units are created from the locked frame without leaving the home unit; frame changes come into a unit as ticked additions and renames only, never deletions, and never touching scores, statuses, weights or amounts. |
| 65 | Diagnostic question instead of a pre-filled move; quick wins on page 6 | Presets seeded solutions into a diagnostic. The field now holds a question until design, with the preset text as a greyed example. Quick wins sit on readout page 6, so the readout stays six pages and its week-6 print is the early read. |
| 66 | Unit economics are entered by the owner, ratios are worked out (owner review, 2026-11-25) | EXCO asked for revenue, manpower vs non-manpower cost and manpower productivity per unit. No app held these. The owner enters five numbers per unit; the ratios cannot be typed, so they cannot disagree with their parts. A missing part gives no ratio, never zero. Org Modeling's head-count and people cost are offered, never imposed, and people cost is labelled base salary only. Figures are an estimate until Finance validates them. The period and volume measure are frame, so every unit is measured the same way. |
| 67 | Structure numbers travel as numbers | Spans and layers arrived as sentences. An optional `metrics` object on `structural_baseline` findings carries them (format still 1.0, additive). Until Org Modeling sends it, the Compass reads the existing wording, so nothing breaks in the meantime. |
| 68 | Accountable beside who decides, and the owner may correct it | "Who decides" alone hides the most common design fault: authority and accountability in different places. Optional `on_paper`, `decided_by`, `accountable` and `accountable_contested` on decision findings; page 3 shows all three and counts mismatches. The owner's correction is stored beside the sending app's value, marked, and logged, never overwriting it. |
| 69 | Readout stays six pages | The structure table shares page 4, so the anchor-role table shows three rows there when it is present (the Compare tab has them all); long finding details are clipped to two lines in print on the two densest pages. |
| 70 | Sixth question: who owns and updates the SOPs (owner review, 2026-11-25) | Process Map Studio already records each document's owner, version date and controlled copy, but nothing reached the Compass and nothing said who updates an SOP or when it is due for review. Each unit now keeps a short SOP register (roles only), typed by the owner or imported as `sop` findings (`SOP-nn`, minted by Process Map Studio) and correctable. A unit starts with an empty register: SOPs are the unit's own. Review is judged against the review-due date, or 24 months from the last review or version when no due date is given. |
| 71 | Every imported figure can be typed over | Owner rule: manual override wherever it applies. Unit economics, decision rights, SOPs and now spans and layers can all be typed or corrected; a typed value wins, the sending app's value is kept beside it, and the change is logged. |
| 72 | Process owner and steps and handoffs per value stream (owner review, 2026-11-25) | An SOP can have an owner while the process as a whole has none, and steps and handoffs were visible only inside Process Map Studio. Both are now kept per unit, keyed by the value stream's `VS-nn` (the same in every unit, so the process lines up). The process owner is one value per unit, edited on Hand-off or Findings, and travels in the packet. Counts come from Process Map Studio's `process_summary` or are typed; a typed figure wins, the app's stays beside it, each change is logged. A new unit starts with none: each unit names its own owner. |
